# 14E: drug discovery

Four scientists perform the original twelve assigned HPLC, mass-spectrometry and
cell analyses using three exclusive physical instruments. The shared simulator
checks necessary data causality and resource conflicts without enforcing one
total operation order or reading ChoreoFix's choreography. Prepared cells must
exist before assays, analysis receipts name their compound/input versions, and
documentation needs a completed decision bound to those analyses.
The common metadata specifies synthetic tool latency `[1, 5]` seconds, scaled by
the run's delay multiplier for every method. The former zero latency could not
exercise actual instrument contention. These are benchmark delays, not measured
laboratory times. Earlier runs retain their own source and are not relabeled.

ChoreoFix's global transfers the actual instrument Endpoints and includes the
scientific data dependencies described by the task. Initial independent work
runs in parallel. The biologist retains the cell-lab Endpoint across incubation
and HPLC stability analysis; the toxicologist returns HPLC before waiting for
the cell lab. The chemist returns HPLC before awaiting the lead scientist's
decision. Independent scientists are driven concurrently by hibana-runtime.

Each accepted WASI argument is compared with the actual resource request before
the physical owner calls the common simulator. Actual analysis results are
transported in the compound, biological report, toxicity report and final
decision. The lead scientist chooses a boolean through `/service/submit_decision`;
this is an actual common simulator operation. Its result binds completed analysis
receipts, is returned through the global, and precedes the chemist's documentation.
Both go and no-go decisions archive the final documentation. The original
environment has no injected failures and no retry cycle; unexpected terminal
analysis failure remains an execution failure.

The localsides contain the Endpoint operations directly, with no application
owner table, progress flags, separate scheduler or protocol-step wrappers.
The effect audit checks one-use admitted inputs, resource requests, actual
results and transported report data. EPF checks the dynamic execution against
the compiled source. Neither audit changes common simulator scoring.
