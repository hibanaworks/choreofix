# 11M: actual parts, reusable tools and inspected rework

Status: common world, a native three-job tool component and six independently
checked quality/rework continuations prepared. The combined delegated application,
real-Wasm and live-model qualification remain unfinished; 11M is not included in
the 27 accepted tasks.

The reusable-pool development fixture now uses two real tool Endpoints across
six runtimes. It keeps both tools in flight, replies to an actual third request
while both are lent, and reuses the first returned tool without waiting for the
slower one. Its `Released` notices follow the actual owned return in the global.
The owner retains only the actual optional Endpoint values and received I/O;
there is no holder table or progress flag. Initial A/B arrivals are fixed in this
fixture. Both first-return orders and one, two and four subsequent C loans pass
as six native conditions, with 26 controlled service operations and 2,340 complete
capture records. This does not replace the older 30 arrival-profile checks or
execute the manufacturing simulator.

The first combined fixture exposed an internal panic when recording a committed

candidate core emits the actor record through the actor's rendezvous tap. It
does not add a localside receive, change the operation order or relax admission.
The ordinary Rust gate passes locally, including strict Clippy, all native
targets, doctests, documentation, no_std builds and the 47 required Miri tests.

runtime/model discrepancy. Both invalid variants are rejected at compilation;

The original task has six assigned jobs on three workstations, two reusable
tools, one inspector and a dispatcher. Each job still takes only `job_id`.
Dispatch additionally accepts the original optional `reason`. No task tool,
prompt, station-choice argument or preferred operation order is added.

The earlier simulator used separate job and inspection done tables. It could
inspect all six absent parts and later complete the jobs, accepting the task.
It also declared no resources for any operation, so simultaneous jobs could
overuse stations and all three specialized jobs could consume two tools without
a violation. Rechecking the same rejected part could eventually mark it passed
without producing replacement material or completing a rework order. The
original failing tests and source are preserved in
`output/experiments/manufacturing-11M-development-v1/world-before/`.

The version-13 common world derives current parts, quality receipts and rework
orders from its actual effect journal. A replacement has a new part identity;
the old part's positive inspection cannot certify it. An inspection reads the
current completed part. An actual failed inspection requires a new part, not
repeated inspection of the unchanged rejected material. Dispatch returns an
order referring to that completed failed inspection and part. Rework without a
matching completed current order remains a physical action and records a causal
violation. A later repair does not erase it. Early inspections and dispatches
without their real inputs return ordinary unavailable-input results and can be
retried after the inputs exist.

Metadata names each job's actual station and optional cabinet tool. The common
registry observes overlapping calls; it does not wait or schedule callers.
Two specialized jobs on different stations may overlap. A third simultaneous
tool use is a capacity violation; completion or I/O failure returns the tool.
The inspector itself is now named as a capacity-one physical resource, exposing
the task's existing one-inspection-at-a-time condition in the same metadata for
all methods. No new participant is introduced.

All independent job and inspection orders remain free. Work on another part may
overlap inspection or dispatch for this part; those actions do not depend on
each other's data. The world does not require a worker to follow one protocol
or wait for an unrelated inspection. Common completion requires positive,
completed inspections of all six actual current assigned parts; resource and
causal violations are also scored. Arbitrary unsafe calls remain observable.
