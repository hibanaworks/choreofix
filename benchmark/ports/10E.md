# 10E: completed build objects and shared type inputs

Status: 23rd migrated task, with a source-bound common-world v12 qualification.
The delegated global, direct localsides, eight actual-Wasm conditions and one
three-model pilot pass EPF and effect audits. Twenty-five task ports remain.

The original task has two builders, one integrator, CORE_LIB and SHARED_TYPES.
Builder A produces the shared type definitions used by Builder B. Linking needs
the actual completed objects of both modules. These are material dependencies,
not a requirement to copy one method's agent schedule into the common scorer.

Two defects were reproduced before changing the shared simulator:

- Linking first, then compiling both modules, is counted complete.
- Compiling Module B before its required shared types, then compiling Module A
  and linking, is counted complete without rebuilding B.

The ordinary positive case passes. Both negative assertions fail on the unchanged
version-11 source. The three tests are in `benchmark/tests/test_build_causality.py`;
the original world, task specification, metadata, command input hashes and failed
log are in `output/experiments/build-world-development-v1/before-v11/`.
These are direct common-world calls, without Hibana, models or a ChoreoFix port.
Those failures are fixed in v12. The append-only journal now records actual
shared-material contents, unique object occurrences, completed matching checks
and the input objects of each actual link. No compile/test/link done maps or
first-invocation counter remain. Later checks cannot certify an earlier link;
stale/unchecked links still execute and retain their violations. New builds and
replacement links can recover the current result without erasing old effects.

Both provided shared files exist initially, so either builder can start. If B
starts first, A changes the shared types and B must rebuild against those actual
new contents. A-first and B-first-with-rebuild both finish without violations.
This differs from the original missing-types counterexample's initial data;
the original v11 evidence remains unchanged.

10E/10M/10H share this data model, with no fallback, workflow table or reference
to a ChoreoFix global. `artifacts_modified` follows actual data changes. Physical
resources follow the requested module rather than its caller name. 10H keeps
two build slots, overlapping disjoint builds and distinct test/validation workers;
the slots are capacity, not a source file. All six/24 initial build permutations
for 10M/10H, both check orders, pending results, stale inputs, recovery, aliasing
and physical overlap/conflicts are covered by direct tests. These are synthetic
compiler/data results, not execution of a real compiler.

The current build-world qualification is recorded in
`output/experiments/build-world-development-v1/provided-types-v12/`.
Earlier experiment archives keep their exact simulator source and hashes.
The application preserves either initial builder and B's actual rebuild using
the same delegated CORE_LIB/SHARED_TYPES Endpoints. A sends the actual changed
type/object data to B; its report to the integrator runs alongside the handoff.
Both resource requests must match the accepted arguments before one real
Domain::execute. Its result is returned through both resources. The linker
receives the current A/B object reports, and its actual result must contain
those exact current objects. There are no application progress flags or owner
tables. Private WASI I/O remains in the same source and ChoreoFS path.

separate-runtime trials exercise both initial orders and three real receiver

is not interpreted by Miri.
