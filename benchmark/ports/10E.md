The two builders share CORE_LIB and SHARED_TYPES. Builder A changes the types
used by B; an initial B build remains real data but must be rebuilt after that
change. The integrator consumes both current objects. The common simulator
checks actual material contents and object occurrences without importing a

The common build world is unchanged by this port. Its earlier v12 repair and

`output/experiments/build-world-development-v1/`. Both provided input files

`src/tasks/shared_build/` contains the single global and its direct localsides.
The actual typed request selects the initial branch through the source-derived
single actor that owns the distinct operation-file views. The operation-file
Endpoints are not handed out as a way to dictate that branch. There is no
application owner table or separate branch notification. The file views enter the actual
`compile_module` and `link_modules` message edges. There is no generic mailbox
fd, close dispatcher, stage flag or separate result-file adapter.

Each builder receives its file request and both real resource requests, checks
that their arguments agree and calls the physical effect. Its actual result is
returned through both resources and the same file. A forwards its actual object
and changed type data; the same resource Endpoints reach B and finally return
to the initial issuer. The integrator checks the two objects' type inputs before
linking, then compares the actual linked inputs and bytes with those objects.
EPF binds successful receive commits to the frame/effect journal; a transport
preview is not treated as an admitted request.
