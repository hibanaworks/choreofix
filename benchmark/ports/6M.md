# 6M: two features, independent review/test preparation and integrated CI

Accepted as task 26 of 48 on 2026-11-11. Six actual five-Wasm conditions and
one current-source five-model pilot pass common scoring, complete-capture EPF
and the independent effect audit. These are source-bound qualifications, not
scored comparisons or final-source certification of every family.

## Protocol and effect boundary

The whole global connects implementation, test preparation, review, publication
and CI. Each feature's actual Endpoint moves developer → reviewer → developer
→ CI runner. A rejected review or failed CI returns that continuation for fresh
implementation, tests and review. Successful final CI removes the editable
continuation. Independent preparation and the other feature remain concurrent.

The actual REPO, TEST_ENV and BUILD_SERVER Endpoints carry their own requests,
results and returns. TEST_WRITER receives TEST_ENV once, uses its continuation
for both features in either order, and returns it once. CI receives the actual
feature and BUILD_SERVER requests and compares both with the admitted suite
before executing the backend. Successful results bind the current publication,
repository bytes, test occurrence and complete test definitions. Ordinary
negative tool results remain negative results. There is no application owner
table, task flag, second progress machine or localside ordering workaround.

The guest uses ChoreoFS for its private and shared WASI operations. Five actual
Luna participants choose shell commands and private calculations. Reviewer and
test writer choose their initial feature order; no prescribed command transcript
is used in the model run. Typed requests independently reject wrong targets and
changed admitted arguments before an effect.

The common environment grades actual source bytes, matching completed review
and test receipts, publication occurrences and subsequent CI. Unsafe effects
remain observable; later evidence cannot repair their violations. Failed CI of
the current publication permits content-bound repair without requiring positive
CI of that broken base. Independent valid orders remain free. These are abstract
development-tool outcomes, not execution of a real compiler or proof of the
correctness of arbitrary submitted programs.
