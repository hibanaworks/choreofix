## 2026-11-18: blocking-receive repair and required requalification

At this checkpoint the depth-2 model trial had timed out. Replaying its shell
calls through Wasm reproduced its committed operations and located the wait at
the first peer-review read. The November 20 qualification above uses its own
recorded source and executable.

The earlier EAGAIN probe demonstrated that a nonblocking caller could continue.
It did not prove that the obsolete blocking receive was correctly refused. The
claim that this was solely arbitrary agent behavior was premature. The old
native reviewer had left an initial-review roll that the global still allowed.

The current rewrite hands the actual REVIEW_A/B Endpoints from initial review
to their CI-repair participants, then to the repository after successful CI.
Actual review and CI values travel on the global's Endpoint messages; no phase
flag, holder table or alternative host path was added. CI consumes publications
in a direct offer loop. Final-result messages identify its explicit completion
continuation; offer does not preview an unconditional outgoing TaskExit.

The third recovery case, where both features were initially rejected, initially
still blocked on the ordinary peer-review read and reached its 180-second
mechanism deadline. That failure is preserved in
`output/verification/post-core-regression-20261117/v25/feature-delivery/`.
A core actual-Endpoint regression then reproduced the missing refusal:
a file participant learns a permanent resource handoff through the repository,
but its old rolled receive returns Pending. It must return recoverable
Unavailable so the legal continuation remains usable. The first direct probe
fails before the borrowed-view probe is reached. The preserved test, hash and
failure are in `../hibana/output/validation/retired-receive-20261118/v2/`.

The core now derives an immutable causal handoff witness and consults existing
receive completion on the same FIFO direction and lane when classifying an
empty old receive. A notice from another direction cannot seal it. Already accepted
messages can still be drained, including messages from another visit delivered
after the notice; no live owner table or progress flag was added. The minimal
case, arrived notice, borrowed view and accepted-message counterexample pass
core native and strict-provenance Miri tests. This classifies an impossible
empty wait; it does not guarantee termination of arbitrary agent reconsideration.

## Authority and actual effects

The actual REPO, TEST_ENV and BUILD_SERVER Endpoints are issued once and moved
to their physical effect owners. Six file Endpoints go directly to the five
guests. Each operation file uses its actual typed request and reply through
ChoreoFS. The generic close mailbox, task dispatch adapters, per-operation loan
broker and old native-only workflow fixtures have been removed.

Both features prepare in parallel. Review and test preparation are independent;
the reviewer and test writer choose their initial targets independently. Each
attempt publishes its actual candidate and interface change. The completion
path retries after actual review rejection; the global's rolls retain their
ordinary elastic semantics. Both initial preparations join before integration.
Either approved developer can submit the first merge. The repository receives
the actual request and the corresponding global branch runs its CI and any
required repair before the other merge. Both developers can read their own
approval before choosing when to submit.

Developers may provide fresh nonempty source bytes after failure. The receiver
checks the actual current candidate, approval, publication and CI/test receipts
before effects. A failed CI requires new implementation, tests and review before
remerging. Result files carry actual data; no owner table, progress flag or
second workflow decides permissions. The global is the sole coordination
specification and localsides directly drive their Endpoints.

The five agents freely use wash commands and private files. Requests use their
original JSON arguments and results are read from the same operation file.
Read-only candidate, review, interface, merge-ready, publication and CI files
carry actual messages. There is no host-selected command recipe or
approval-submission envelope.

## Defects found and their scope

The repository localside formerly treated a received review as permission to
send feedback immediately. A retained incoming continuation may arrive before
the current parallel test reply; a new outgoing action still requires that
reply. The core correctly refused the premature send. The corrected localside
stores actual review data and follows the next enabled `offer()` operation.
No application readiness flag or core admission relaxation was added.

EPF's initial candidate excluded nested retained overlaps. The saved deep record
stalled at the early approval receive, despite the existing source grammar
supporting it. The constructor now uses the existing alongside rule when one
actor begins the later body before its incoming continuation and finishes it
afterwards. Source readiness, complete capture, exhaustive search and final
execution checking are unchanged. The compact regression checks the legal
source word and rejects a premature outgoing continuation. All 161 native tests,
Clippy, doctests, no_std/Pico builds and six Lean modules pass; the new regression
also passes strict-provenance Miri in EPF. No application Miri ran.

The agents' private files exposed a stale audit assumption: the canonical
private WASI close result has three bytes. The journal now validates the
runtime's actual request/reply codec, checks fd pairing and rejects truncated
or extended payloads. The original model execution was re-audited; agents and
effects were not rerun. The six mechanism inputs contain no private-I/O close
pairs, so their predicate is unchanged by this codec repair. That continuity
is recorded in `close-codec-continuity-v69.jsonl`.

The verification driver now consumes one audit result when also checking record
mutations. Removing the duplicate EPF call changes no input assignment or
validation predicate. Interrupted and failed diagnostics remain outside the
accepted matrix; their statuses were not relabeled as successful.

The common simulator grades actual material and result causality for all
methods. These abstract development tools do not compile arbitrary source or
certify software security. Remaining work includes the other 21 direct task
ports, the unfinished core generated population, final-source all-family
certification and planned experiments. Historical pre-direct-boundary 6M results
retain their original scope and are not pooled with this qualification.
