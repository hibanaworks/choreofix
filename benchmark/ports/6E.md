# 6E: independent feature protocols and direct operation files

This is the twenty-second source-bound direct-file task; twenty-six of the
original forty-eight remain. Its source and evidence are identified by
`output/experiments/review-direct-files-20261115/qualification-v45.json`.

Eight files use four guest-owned Endpoint views. Developers submit actual
implementation/merge arguments and read actual results from those same files.
Their read-only review streams contain actual review results. One reviewer
agent freely uses two review files, each bound to its own real Endpoint. Two
direct localsides own the independent review computations and actual results.
No command recipe, generic mailbox, phase dispatcher, progress flag or separate
permission table controls these operations.

Each feature directly joins its implementation result and actual review request.
Only rejected attempts repeat; approval and merge sit outside the roll. Both
features run in `par`, allowing either initial target, repeated or alternating
rejections, independent revision/review and merge/review. The previous global's
outer roll enclosed positive completion and allowed a fresh review after both
approvals. The new global fixes that repetition boundary. All thirty-four
mechanism conditions retain their duplicate/early/malformed-request checks,
including third and fourth rejections. Timing stimuli separate invalid-input
probes from work and submit the selected first target's real implementation
before the other initial implementation. Both requests precede result waits;
production localsides, simulator delays and overlap expectations are unchanged.

The repository has one affine Endpoint, initially delegated to its effect owner
and retained until run end. Actual file requests reach that view directly before
Domain::execute. Actual results return to the corresponding file. The former
file -> developer -> admission -> resource loan -> second request pipeline and
manual cross-feature interleaving enumeration have been removed.

All 34 real-Wasm conditions pass protocol completion, complete dynamic EPF,
one-use request/effect/reply correspondence and neutral common scoring, with
zero violations and 3,080 rejected record mutations. All normal-delay cases
observe implementation/review and merge/review overlap. Both first-target
alternating depth-two cases observe three implementation/review overlapping
pairs. The final checking binary is
`833ce2cf007c04bf6cda7597a9f0afb07268a429029c4b3b0599aa19cc3ccc6c`.
