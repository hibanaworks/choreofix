# 12E kitchen: delegated equipment and completed ingredient receipts

Accepted as task 27 of 48 on 2026-11-11. Thirteen real-Wasm conditions and
one three-model pilot pass common scoring, complete-capture EPF and the separate
effect audit. These are finite, source-bound qualifications, not scored
comparisons or final-source certification of every family.

The task retains three chefs, one oven and one stovetop. A and B need both
equipment resources for their base dish; C needs the oven. Ingredient preparation
needs no equipment in 12E. Sauce goes A to C, garnish B to A and glaze C to B.
Each final dish requires its own actual completed base and the correct actual
completed ingredient. Independent ingredient preparation does not wait for bases.

The version-14 common world also covers 12M's equipment-dependent ingredients and
12H's multi-step preparation/cooking/recovery. This is shared outcome scoring for
all experimental methods. It reads no Hibana global, source snapshot or EPF trace.
It observes physical resource use without locking or scheduling tool calls.

## Reproduced problems and repair

The prior basic world accepted nine wrong-content calls and returned task complete
with no violations: all three ingredient destinations, base dish names, and final
dish/ingredient names were wrong. It also treated in-flight preparation as an
available input. The multi-step world accepted cooking an unprepared wrong item,
preparing the wrong dish afterward, and plating wrong dishes/ingredients; twelve
calls completed the task without violations.

World effects now retain their actual request/result values. A combination names
its completed base and ingredient occurrences; a multi-step plate names its actual
preparation, successful completed cooking and completed ingredient. A failed cook
consumes its preparation: an unchanged old prep cannot authorize a retry. A fresh
independent prep may finish while the failed cook's reply is in flight. Incorrect
or unavailable inputs return failure and can be reconsidered. Returned result
objects cannot rewrite the journal. Whole-task success waits for completed final
effects. Old prep/cooked/done tables and unused acquire/release methods are removed.

## Delegated global and production receivers

`src/tasks/kitchen/global.rs` now defines the complete 12E business protocol and
three private-I/O projections, with eleven roles. The cooking owner lends the
actual oven and, for A/B only, the stovetop. Both resource Endpoints carry the
actual typed request, both results are delivered, and both Endpoints return.
The service compares each request with the actual admitted input before its one
effect. Resolvers inspect only the actual first and second requests; there is no
owner/progress table. All six base-user orders exist in the global.

Ingredient requests run independently of equipment use. Their actual result is
sent to the producer and consumer immediately, without waiting for the producer's
oven turn. Each chef finishes its preparation work and receives its ingredient
before combining its own dish. The finish owner drives the three real requests
independently; it has no all-chef completion barrier. Endpoint operations remain
directly in the cooking, ingredient and finish localsides.

The native receiver qualification passes five task-specific functions. Twenty-four
controlled input schedules cover all six equipment orders, two ingredient-delay
profiles, and a control withholding the last chef's base request until the first
chef's dish has actually finished. All complete with 216 fixture effects; every
base uses the oven exclusively and all five resource loans per case return.
These controls change test input arrival, not production scheduling or world rules.
An initial test used two fragments for a four-fragment associative `par`; correcting
the test to the public projection's four fragments required no core/global change.

Both actual resource-receive legs reject four malformed payloads apiece before
any Domain call. Those eight inputs pass strict-provenance Miri. Two separate
data functions also pass Miri; native Clippy passes. The exact source and
dependency hashes, native executable and all 24 fixture journals are in
`output/experiments/kitchen-development-v1/native-v7/`. The source is unchanged
across these checks. Miri uses its required nightly compiler and a polling test
clock; native runs use stable and the actual host driver. The two data functions
take 13.90 seconds under Miri; the eight receiver inputs take 303.26 seconds.
The guarded native/Miri sequence peaks at 454,410,240 bytes.

Native fixture journals retain all their actual effect data. The separate
transport observations are only the remaining undrained diagnostic records;
they are not a complete producer capture and have not received a dynamic EPF audit.
These are finite protocol/receiver checks, not real-Wasm or live-model experiments.
CI runs the five kitchen functions without repeating the imported shell tests,
and includes the actual receiver's eight Miri inputs.

## Actual Wasm and live-model qualification

Three independent wash guests use the same eleven-role global and production
receivers. Shared and private file operations pass through ChoreoFS. Each chef
may request its base or ingredient first. After both of its own operations, its
next combine-file close remains a borrowed WASI request until the actual incoming
ingredient arrives; the prior command is not held waiting for that peer. There
is no application phase flag, owner table or second coordinator.

The common qualification entry assigns all six equipment orders and both request
orders, then a thirteenth invalid-input/pipeline condition, each in a separate
process. It checks the actual thirteen reports for missing or duplicate conditions.
The last condition checks early and duplicate requests, invalid targets, private
files and chunked arguments. Each dish completes before the next chef's base
request, demonstrating that the global does not impose an all-chef completion
barrier. Three ingredient commands are issued concurrently. The common world
has zero configured operation delays here; this is not a cooking throughput or
long-running effect-overlap measurement.
