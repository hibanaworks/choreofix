The revised boundary is qualified as task **18/48** on 2026-11-15: 51 actual-Wasm
conditions and one three-Luna/xhigh pilot pass complete-capture EPF, independent
request/effect/reply matching and the neutral common score on each same run.

certification and scored comparisons remain unfinished.

Each chef owns three ChoreoFS operation-file Endpoints:
`/service/prepare_base_dish`, `/service/prepare_ingredient`, and
`/service/combine_dish`. Responses are read from the same operation file.
There is no generic request/result mailbox, close-to-business dispatch,
shared decision cell, application owner table or progress flag.

The original three chefs, one oven and one stovetop remain. A/B need both actual
equipment Endpoints for their bases; C needs the oven. Each actual equipment
request must match the admitted file request before the base effect executes.
Results pass through the actual equipment Endpoints before their return.
Ingredient preparation needs no equipment. Sauce goes A to C, garnish B to A
and glaze C to B. Each final dish uses its own completed base and the actual
completed incoming ingredient, including the common world's receipt IDs.

Independent material preparation and per-dish completion remain available.
The global allows all six equipment orders, rather than the localside choosing
one order through shared state. A chef can finish its dish before another chef
requests a base, and before preparing its own outgoing ingredient; each chef
still completes all three assigned effects before exiting.
