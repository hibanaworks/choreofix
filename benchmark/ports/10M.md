# 10M — overlapping build inputs

This is the 24th source-bound qualified task, out of 48.
The current common environment is version 12; no comparator or simulator
procedure has been changed to follow this choreography.

## Implemented path

`src/tasks/cascading_build/` contains one 478-event global and all 15 projected
roles. Its six initial permutations preserve the three pairwise resource
conflicts. Each builder receives its two actual resource Endpoints in parallel,
sends the admitted arguments and both resource requests, receives the real
result and returns both Endpoints. Initial shared-material updates notify the
affected builders. A separate physical test worker serializes tests; the global
allows testing a completed object during another compilation.

The compiler retains actual objects and completed test receipts. The integrator
receives that candidate, selects an actual stale/failed object, and sends its
exact repair context through the global. Its resolver input is that received
candidate, not an owner map, progress flag or selected-step cursor. Every failed
test is followed by a fresh object occurrence before another test of that module.
Before linking, all three editing Endpoints leave the repair continuation.
The linker checks the actual current objects, completed positive tests and
returned link inputs/bytes.

The five WASI participants use the real wash guest and ChoreoFS. Their direct
localsides contain the Endpoint operations; the model's own file-close arguments
become the admitted requests. Actual feedback, updates, reconsideration context
and final link results are returned to the guest. Private shell computation
remains available. The compiler is the common environment's synthetic object
data model, **not a real compiler execution**.

## First live-model pilot

Evidence: `output/experiments/model-qualification/current-core-cascading-build-10M-v1/qualification.json`.
The preregistered first run uses five Luna xhigh participants through the existing
ChatGPT subscription, original depth 2, initial order ABC, normal delays, seed 0,
no extra failures and no barriers. All five participants and wash guests finish.

* Elapsed time: 115.339465333 seconds; inclusive usage: 769,827 tokens. Cached
  input is included; reasoning is already included in output tokens.
* Five actual model turns overlap. Fifteen effects comprise seven builds,
  seven tests and one link; one build/test pair overlaps. Stale initial objects
  and two injected failures lead to fresh builds and successful checks.
* Common score and protocol complete with zero violations. EPF checks 37,719
  captured records against 97,331 expanded source events. Independent actual
  effect/receipt auditing passes. Eleven whole-run record mutations are rejected.

The first whole-run audit exposed an omitted `simulator_complete` report field;
the effect checker already required that score to be complete. Reporting that
checked value fixes final aggregation. A second audit-tool correction makes the
missing-tool-reply mutation remove only the response, preserving client RPC
requests that share its ID. The corrected mutation is rejected for incomplete
tool exchanges. Both repairs concern saved-record tooling. The original model
execution, global, localsides and runtime binary remain unchanged. The raw outcome
and measured runner are retained; the final auditor and changes are archived
separately. No model rerun was needed.

## Remaining scope

This is finite source-bound mechanism qualification and one unscored pilot.
It does not estimate success rates or establish comparative superiority, real
compiler correctness, arbitrary Rust refinement or final-core/all-family
certification. Twenty-four other task ports, the incomplete core generated
population and formal scored experiments remain outside this result.
