## Common world

The original public schema requires `test_type`, while the old implementation
read `tests`. An empty result could mark a configured panel complete. Fuzzy
patient matching and per-step done maps could also complete the wrong or stale
case. The original source and executed failing tests remain under

baseline test-file hash was not captured; that provenance limit is explicit.
No historical implementation is restored for a sensitivity rebuild.

The repaired world records completed patient-result occurrences and exact
current inputs. Invalid arguments do not create clinical artifacts. A panel
can be built from separate valid `test_type` requests. Diagnosis requires the
same patient's complete own-panel results and, where configured, completed
matching image interpretations. Pending results cannot be used. Reassessment
and replaced image/test inputs invalidate their actual dependents.

Independent general and specialist panels do not consume each other's results.
Neither may be forced to wait for the other just because one example lists
them sequentially. A later general-panel result does not invalidate an
independent cardiac result. The completed assessment is their common input.
Imaging and caller-data medication review also remain independent. Review
preserves the optional supplied medication string; there is no invented
requirement to diagnose before reviewing that data.

## ChoreoFix protocol under construction

The initial assessment precedes an explicit referral. General tests, actual CT
work and cardiac tests can then progress independently. Both doctors share
actual findings, and the cardiac request reaches its effect owner before the
actual diagnosis result is returned. Medication review is an independent
branch, with its real result communicated to the ER doctor. These messages are
visible in `src/tasks/medical_consultation/global.rs`.

CT is the actual exclusive resource. Its owner admits the imaging argument,
lends the unique CT Endpoint, receives the actual request through that same
Endpoint, compares the values before the effect and returns the actual result.
The caller then returns the CT Endpoint. Clinical services consume projected
requests directly. No application workflow cursor, holder table or approval
flag is added.

Each panel has its own affine Endpoint for the actual test-result object. The
service lends it for each request and consumes its return. Actual receipts
choose partial versus complete; completion transfers the panel away from the
retry owner. Latest actual receipts are stored by test name, so storage does
not grow with reconsideration count. Two hundred replacements and rejection
of stale/foreign updates are checked without partial mutation. This is actual
result data, not an application progress or ownership table.

## Claims requiring separate evidence

The public domain tools do not include prescribing, drug administration,
referral or findings delivery. Domain-call completion alone therefore cannot
certify those missing effects or communication channels. ChoreoFix's actual
referral/findings traffic needs Endpoint/EPF and content-correspondence evidence.
Medication review cannot establish review-before-administration when no
administration effect exists. Do not claim all eight original checklist items
from the common world's completion bit, or make the scorer enforce ChoreoFix's
chosen procedure. Any common-interface extension must be versioned and applied
equally to every method before its results are collected.
