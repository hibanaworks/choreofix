This is the fifteenth Wasm-migrated task. It passed all 64 native/EPF conditions,
two actual-receiver negative probes, five actual-Wasm conditions and one
five-model pilot. It contributes no scored comparison results.

## Participants and tool interface

The common task in `benchmark/descriptions/4M` and
`benchmark/environments/4M/sim.py` retains the upstream five agents: ARCHITECT, DEVELOPER_A, DEVELOPER_B,
REVIEWER and TESTER. The architect proposes both module refactors. Each developer
changes its own module and SHARED_LIBRARY. Both modules are reviewed, tested and
merged. Its outcome definition was revised explicitly as described below;
the task is not an unchanged upstream task. The original tool keys are `title`, `target`, `pr_id`, `suite` and
`branch`, respectively. Original review/test failure injection is disabled by
this environment's empty `_DECISION_TOOLS`; this port does not invent a retry
loop or discard a negative result as success. A terminal failed domain operation
aborts the run before a dependent merge.

The original resource metadata associates refactor/merge with REPO and tests with
TEST_ENV. Design and review have no shared resource requirement.

## ChoreoFix procedure

The first actual design request chooses which developer writes first. The other
design runs concurrently with that developer's work. Within each developer's
exclusive repository loan, either its module or the shared library may be
changed first. After that shared-library change, the repository is returned and
loaned with TEST_ENV to TESTER, which runs both dependent suites. Only after both
results and both real Endpoint returns may the second developer modify REPO.

After the second developer returns REPO, the current candidate is delivered to
the reviewer and the physical review service. The first actual review request
selects review/merge order. Its effect runs concurrently with the second full
test round. The first merge and the other review are independent parallel
branches. Each merge consumes the actual normal request and the resource
request; their arguments, candidate, actual review and actual test results must
agree before the original domain operation is invoked.

Holding REPO during testing protects the candidate being tested from a concurrent
write. This read/candidate dependency is stronger than the upstream resource
metadata, which lists only TEST_ENV for `run_tests`. The resource metadata is unchanged. The corrected common simulator accepts
both batched edits and tests after merges; it does not require this port's
stronger pre-merge retesting procedure. The two test rounds are reported together to developers
before merging. Independent design/review effects do not acquire REPO.

The physical owners retain actual design, change, test and review values, and the
real resource Endpoints. There is no holder table, progress flag, alternate task
state machine, generic phase driver or second coordination graph. Communication
and parallel completion boundaries remain visible in each localside body.

## Qualification domain

The native matrix has six independent binary choices: first design/developer,
A's change order, B's change order, first review, first test-round suite order and
final suite order. All 64 combinations are required. Each drives real Endpoints
across two runtimes and produces fourteen fixture effects. Both positive
completion and actual review/test and merge/review overlap are checked.

The native fixture holds selected effect calls until the independent effect has
started. Those paired barriers test that the projected protocol and executor can
make concurrent progress; serialization reaches the deadline. They are
explicitly controlled scheduling witnesses, not natural model timing or
performance measurements. No fixture barrier is part of the application owner.

Natural timing is reported separately. In the first normal-delay Wasm record,
the second review completed while tests were still running, before either merge
started. Its zero merge/review overlap is valid early execution, not evidence of
serialization. The native controlled schedule retains its strict requirement
that independent merge/review effects can both make progress; ordinary runs do
not require them always to coincide in wall-clock time.

Before assertions, each completed condition saves its actual effect intervals,
producer captures and checkpoints. The successful path also asks EPF to construct
and check a source execution from the sealed program used by the Endpoints.
Separate actual-receiver probes substitute resource arguments and address the
wrong module; neither may invoke `refactor_code`.

The subsequent full-source native run also composes all five WASI private-I/O
choreographies with the business global. Its 64 conditions passed EPF with
896 fixture effects and 22,336 capture records, including terminal I/O exits;
the two receiver negatives also passed. This still drives native Endpoints,
not actual Wasm guest instructions or model participants.

The native fixture is not the original simulator, a Wasm guest or an AI. Actual
Wasm driving, common-simulator scoring, independent effect/record mutations and
live-model qualification are recorded separately below. Final-source consumer
checks remain required. The native protocol fixture remains synthetic;
it does not establish correctness of arbitrary source-code refactorings.

## Method-neutral common environment

The actual original ToolRegistry accepted a twelve-call reversed sequence with
merges first, designs last and no post-change retests as complete with zero
violations. Its captured counterexample is saved separately from successful
experiments. An intermediate sequence-based scorer was withdrawn and its
implementation deleted. It was never used in a scored or model experiment.

`common-environment-v2` additionally requires completed exact-content review and
test receipts at publication time. Version 1 incorrectly allowed later validation
to cover an earlier publication. Mechanical publication remains observable;
publishing without the required evidence records an unsafe effect, which later
validation cannot erase. Updating a published shared dependency also needs
evidence for the affected modules. Reviews and tests may be reordered, and
unpublished experiments do not invalidate an already-valid publication. No
choreography is read by the scorer. Physical resource conflicts remain separate.

The revised definition is explicit in its common description. Tests distinguish
independent review/test permutations from invalid early publication, pending
validation, stale-content receipts, shared-dependency changes, real failing code,
idempotent edits, unmerged experiments and physical contention. The executable
Python is trusted benchmark fixture code, never model-supplied source or a host
shell replacing WASI. Earlier pilots retain their recorded original simulator
version. Comparative superiority requires matched measured results.
