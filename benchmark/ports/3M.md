# 3M: research material, factual evidence and paper publication

## Direct Wasm and live-model qualification, 2026-11-18

Three authors, the fact checker, and the editor each run wash in their own Wasm
guest. Each operation file binds its typed request and reply to the owning
Endpoint. Choreography governs chapter transfer, rework, and publication. The
document owner compares the received verdict with the current draft before
publishing that verdict to the author’s read-only file. Supplemental research
continues independently until the author’s actual guest exit. Its typed
request permits other topics and leaves the assigned research evidence intact.

Two scripted actual-Wasm conditions on the same 390-event, 34-role source
completed the original common score. The ordinary condition ran 16 effects.
The second condition ran 24 effects, including supplemental research before
and after the assigned topic and a fresh revision after each kind of rejection.
EPF checked 15,913 complete records across the two runs. The three author guests in
each run tried another revision after approval and received a recoverable
WASI error. The independent audit joined committed requests, chapter loans,
actual effects, file replies, and common scores, with zero violations.

Five Luna/xhigh participants completed depth two on the same runtime binary
in 174.78 seconds with 2,251,389 inclusive tokens. The execution reached
publication after two factual and two editorial rejections. Its 26 effects,
22,434 complete EPF records, and two overlaps between distinct physical
resources passed the independent audit and common score with zero violations.
The auditor also rejected four altered mechanism records covering a changed
request, a changed file reply, a missing repeated request and a missing chapter
loan.

The current native suite passed 30 tests, including five common-world
conditions and 95 effects with native EPF and request/effect checks.
The build, program projection, and recorded runs are indexed in
`output/experiments/research-paper-direct-20261118/v5/verified-3M.json`.

## Earlier native development

The method-neutral `common-environment-v18` scorer binds completed research,
section/reference material, factual/editorial receipts and the actual published
artifact. Later evidence cannot authorize earlier publication. It neither imports
Hibana nor schedules authors. Extra research and independent legal orders remain
available equally to every method. Its 210 behavioral test functions include
48 finite author/preparation order combinations, retries and physical conflicts.
The unchanged task descriptions retain all 48 tasks and 825 checklist items.
The scorer's exact source and checks are recorded in
`output/experiments/research-paper-3M-development-v1/qualification.json`.

The earlier native application source had 132 events and 13 projected roles.
Three affine chapter Endpoints move from their authors through factual and
editorial reviewers to the archive and publication receiver. DOCUMENT and
DATABASE retain their unique physical I/O ownership. They receive each actual
chapter request before executing the effect, and own the current chapter,
reference and research data. Independent chapter work and the two physical
resources can overlap; each physical resource excludes conflicting effects.
No application owner table, progress flag or second workflow cursor is added.

Each chapter attempt performs fact checking and, on success, editorial review.
Either rejection returns the actual chapter Endpoint for revision and fresh
fact checking. This changes ChoreoFix's procedure, not the shared scorer.
It does not remove either check, waive a failed result or impose a barrier
between authors. Only the revision choreography reused by both rejection paths
is factored out. Endpoint operations remain visible in each localside.
Archival additionally requires the review receiver's actual positive
`FinalForFact`, validated against the current chapter and factual evidence.
An elastic roll's completion alone is not evidence of approval.

Publication runs in the actual DOCUMENT owner. After accepting the editor's
`Combine`, it receives all three archived chapter Endpoints, the database
owner's real reference snapshot and the review owner's real results. It checks
current material and positive evidence before `combine_sections`. The database
owner answers an explicit snapshot request and retains its Endpoint until the
publication reply. There is no second publisher, external preparation prefix,
alternate filesystem or separate resource permission mechanism.

Nine native test functions pass, including the whole three-author execution,
all three authors retrying both kinds of rejection, early archival after either
rejection, stale factual data and a missing chapter after another chapter was
really received. Twenty-five publication data cases are included. These are
scripted native participants, not AI or Wasm guests.

Five conditions within that native suite use the actual common simulator for
every effect: depths 0/0/0/1/2 and different author start offsets. All 95 real
effects (16/16/16/21/26) go through the whole Endpoint source; no research or
preparation effect is performed outside it. Each run completes the original
score with zero violations. This is a finite set of executions, not all
interleavings. Every run preserves its real world source hashes, complete
producer capture/checkpoint, compiled source and frame journal.

EPF constructs and checks the dynamic source interpretation for all five runs.
The independent effect audit consumes unique request receives, actual RPC/world
occurrences and the required chapter-authority receives. It checks exact
arguments/results, compiled headers and complete request/effect inventories.
All 47 record mutations are rejected, including repeated identical-argument
request reuse and changing both observations of a frame header. These are
auditor mutations, not 47 runtime attacks. This bounded correspondence does not
prove arbitrary Rust receiver correctness or qualify the whole task.
