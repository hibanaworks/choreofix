## Coordination and physical effects

The global contains two distinct affine workstation Endpoints, LATHE and MILL.
Each technician sees two operation files, `/service/do_lathe_job` and
`/service/do_mill_job`, owning distinct actual file Endpoints. The supervisor's
`/service/collect_reports` owns its actual report Endpoint. There is no generic
request mailbox, subsequent path/phase dispatch, Ready/Busy protocol, callback
selector, application holder table or progress flag.

The actual typed file request chooses the first user of each machine. Its
technician receives the workstation Endpoint, receives and compares the actual
resource request with the admitted file arguments, executes the real effect,
and returns the actual result and resource. These send/recv/par operations are
visible directly in the localsides. File replies and supervisor reports can
remain in flight while the returned workstation performs its next job. Reading
an earlier reply is not a condition for releasing a workstation.

LATHE and MILL are independent. Either technician and either job may start
first. The global additionally permits separate workstation views at the same
actor to operate concurrently; it does not assert an additional capacity-one
human-technician resource. The physical shared capacities are the two machines.
This procedural scope is recorded before qualification. The common simulator
does not grade a preferred choreography or serialize effects: it records actual
machine conflicts, completed job data and the supervisor's actual report.

## Waiting, nonblocking submission and recovery

Ordinary shell redirection is blocking and may wait for a workstation to become
available. It must not be classified as an immediate refusal. Standard WASI
NONBLOCK output, exposed by wash's `dd of=FILE oflag=nonblock`, uses the exact
send Future's preparation phase. A pending source predecessor returns EAGAIN
before transport polling. The same guest can then choose another machine or
retry. Once preparation succeeds, the same Future completes the actual send;
transport backpressure is not falsely reported as an unadmitted operation.
No application adapter or busy flag implements this distinction.

Wrong-job, malformed and extra-field payloads are rejected before a business
send. A successful close means actual request acceptance, not job completion.
Each response is read from the same operation file. The supervisor receives
four actual completed job results before its single collection request; its
public arguments are `{}`, with the neutral simulator recording its default
scope as `all_jobs`.
